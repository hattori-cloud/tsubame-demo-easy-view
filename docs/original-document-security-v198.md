# 原本管理セキュリティ設計 v198

## 基本原則

原本管理は社員管理画面の表示制御だけでは保護しない。
本番では認証・認可・ファイル保管・監査をすべてサーバー側で強制する。

共有デモではPDF・画像・スキャン原本を一切保存しない。
ブラウザーの localStorage に原本ファイル・Base64・Blob URL・署名URLを永続保存しない。

## 書類の機密区分

- 標準: 担当管理者の業務範囲で扱える一般書類。
- 要配慮: 資格証憑など。本人閲覧可または担当管理者まで。
- 厳格: 本人確認・重要手続等。全社管理者のみ。

厳格書類は画面非表示だけでなく、APIでも full_admin を必須とする。
本番では厳格書類の取得前にMFA済みセッションを再確認する。

## 原本区分

- 本人保管・会社は写し
- 会社保管・紙原本
- 電子原本
- 紙＋電子

紙原本の保管場所は「本社 書庫A / キャビネット3」程度までとし、
鍵番号・暗証番号・警備解除コード等の秘密情報は登録しない。

## 電子原本アップロード

1. 利用者を本番認証する。
2. APIで対象社員・書類カテゴリ・担当範囲をサーバー側認可する。
3. 厳格書類はMFA済みか再確認する。
4. サーバーがランダムな storage_key と短時間アップロード権限を発行する。
5. ファイルは非公開Object Storageの隔離領域へ直接保存する。
6. MIME、拡張子、容量、SHA-256を検証する。
7. マルウェア検査が clean になるまで業務画面から閲覧不可にする。
8. clean 後に正式領域へ昇格し、DBへ storage_key / storage_version_id / SHA-256 / scan結果を保存する。
9. 登録操作を監査ログへ追記する。

社員番号・氏名をObject Storageの公開可能なパス名に使用しない。

## 閲覧・ダウンロード

1. ダウンロード要求ごとにサーバー側で本人・担当範囲・機密区分を再認可する。
2. 厳格書類はMFA済みセッションを再確認する。
3. 許可された場合だけ、有効期限60秒を基本とする短時間署名URLを生成する。
4. URLをDB・localStorage・監査ログ本文へ保存しない。
5. ダウンロード／閲覧の事実を actor / document_id / employee_id / 時刻 / 結果として監査する。
6. Object Storage自体は公開禁止・ディレクトリ一覧禁止とする。

## 差替え

旧版を削除しない。

- 旧版 replaced_by_document_id
- 新版 replaced_from_document_id

で相互関係を残す。
旧版は「差替え済み」とし、通常一覧の主対象から外す。
誰がいつ差替えたかを監査する。

## 無効化・廃棄

画面から物理DELETEしない。
誤登録等は archived / invalid とし、actor・日時・理由を保存する。

保管期限が到来しても自動削除しない。
会社の保存年限・法務・監査方針に従って廃棄承認を行う。
電子原本を実際に廃棄する処理は、二重承認を検討する。

## 監査イベント

最低限、以下を追記専用ログへ残す。

- document.create
- document.update
- document.view
- document.download
- document.verify_original
- document.replace
- document.archive
- document.retention_review
- document.access_denied

監査ログには署名URLや原本本文を記録しない。

## バックアップ

- DBとObject Storageを同じ障害領域だけに置かない。
- 暗号化バックアップを別障害領域へ保持する。
- DBのdocumentレコードとObject Storageのversionを対応付ける。
- 定期的に復元試験を実施し、ハッシュ一致を確認する。

## v198 デモで実装していること

- 書類・原本管理センター
- 未確認 / 差替え待ち / 期限30日以内・超過 / 厳格書類のKPI
- 機密区分
- 閲覧範囲
- 原本区分
- 紙原本保管場所
- 保管期限
- 原本確認者・確認日
- 差替え元・差替え先
- 物理削除をやめた無効化
- 書類情報閲覧の監査
- 厳格書類の全社管理者限定
- デモの原本ファイルアップロード欄を意図的に非実装

## 本番開始の停止条件

以下が接続・実機検証されるまで、実社員の原本ファイルを投入しない。

- 本物の認証
- MFA
- サーバー側行・項目認可
- 非公開Object Storage
- マルウェア検査
- 暗号化
- 追記専用監査
- バックアップ／復元試験
- 保存年限・廃棄方針の会社承認


## v200 原本ルール表

カテゴリごとの判断を人の記憶に依存させないため、次の5項目をルール化する。

- 原本の持ち方
- 機密区分
- 閲覧範囲
- 保管年数
- 原本確認の要否

保存年数は、会社決裁・法務確認前に推測して固定しない。
デモ初期値は retentionYears = null、表示は「会社決裁待ち」とする。

ルール変更は全社管理者のみ。
厳格ルールは必ず full_admin 閲覧かつ原本確認必須とする。
担当管理者は厳格カテゴリの新規登録を行えない。

本番では document_policy_rules をサーバー側の正本とし、
フロントから送られた security_class / access_level 等をそのまま信用せず、
API側でカテゴリルールと照合して強制する。
